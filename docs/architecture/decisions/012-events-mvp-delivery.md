# 012. Подтверждение публикации и логирование событий MVP

Дата: 2026-11-08. Статус: принято. Основание: явный выбор пользователя в согласованном плане задания 2.

## Контекст и ограничения

Учебный MVP должен публиковать и читать события с логированием; бизнес-операции в events не выполняются.

## Альтернативы и выбор

Events публикует movie/user/payment в соответствующие топики через kafka-go 0.4.49. Синхронный Writer использует RequireAll, BatchSize=1 и отдельный буферизованный канал результата сообщения в WriterData. Completion возвращает реальные partition/offset. HTTP 201 означает подтверждение Kafka, а не обработку consumer. Асинхронный ответ без подтверждения не выбран, поскольку скрывал бы ошибки публикации.

Consumer с постоянной группой cinemaabyss-events последовательно выполняет FetchMessage → запись результата → CommitMessages. Альтернатива commit до лога допускает потерю результата при сбое. Некорректный envelope фиксируется как invalid_envelope и подтверждается после успешной записи ошибки. Ошибка записи или commit удерживает текущее сообщение для повтора.

## Последствия и риски

После сбоя между логом и commit возможна повторная строка. Пользователь принял этот риск для логирования: вероятность не измерена, последствия не включают денежных операций. ID и координаты позволяют обнаружить повторы. Один брокер не защищает от потери его данных; восстановление зависит от retention и сохранности offsets. HTTP-повтор создаёт новое событие; при сетевом тайм-ауте запись могла произойти. Идемпотентность и Outbox не входят в MVP. До появления необратимых эффектов пересмотреть обработку и восстановление.
