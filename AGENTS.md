# CinemaAbyss: работа с агентами

Это учебный проект с практической целью: пользователь учится принимать архитектурные решения и доводить согласованный MVP до проверяемого результата. Успех означает, что пользователь может объяснить выбор, альтернативы, принятые риски и условия пересмотра.

## Вход в задачу

1. В начале работы с проектом прочитай [текущее состояние](.agents/project-state.md), затем нужное задание в [Project_template.md](Project_template.md). Перед изменением перепроверь затронутые факты по исходникам.
2. Для архитектурного обсуждения используй [порядок совместной работы](.agents/architecture-workflow.md). Начинай с контекста и гипотезы пользователя; существенный выбор остаётся за ним, пока он явно не делегирован.
3. Для документации читай [repo-documentation-guide.md](.agents/docs/repo-documentation-guide.md), для подготовки коммита — [repo-commit-guide.md](.agents/docs/repo-commit-guide.md).

Работай по одному существенному решению. Внутри уже согласованного решения выполняй обычные детали самостоятельно, без повторного согласования. Отделяй требуемое заданием, предложенное, реализованное и проверенное; README сам по себе не подтверждает готовность системы.

## Навыки

Используй установленные навыки по именам из каталога текущей среды:

| Навык | Когда применять |
|---|---|
| `learning-mode` | При объяснении и разборе решений; общий профиль знаний читать штатным способом, не переносить в репозиторий |
| `paseo-committee` | По явному запросу пользователя; агент может предложить комитет, но не запускает его автоматически |
| `project-docs` | При создании и актуализации документов, вместе с локальным руководством |
| `prepare-repo-commit` | При подготовке или выполнении коммита по локальному руководству |

Навыки не копируются в проект. Если нужный навык недоступен, сообщи, какая часть работы зависит от него; не выдавай её за выполненную и продолжай независимые действия. Проектные договорённости находятся в связанных документах.
